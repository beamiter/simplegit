INTRODUCTION                                           *simplegit-introduction*

Simplegit brings GitLens-style Git insight to Vim 9: an inline current-line
blame annotation, a whole-file blame sidebar, file history, diff against any
revision, commit inspection, a repository status window, and hunk handling —
sign-column change markers with navigation, preview, stage and undo.

Rendering stays in Vim9script; every git invocation runs inside a small
asynchronous Rust daemon over a JSON line protocol, so editing never waits on
git. The core UI requires Vim 9.1 with +vim9script, +job and +channel. The
inline annotation additionally needs the +textprop feature (virtual text,
patch 9.0.0067 or later); popups need +popupwin; debouncing needs +timers.
Neovim is not supported.

===============================================================================
INSTALLATION                                           *simplegit-installation*

With vim-plug: >
  Plug 'beamiter/simplegit', {'do': './install.sh'}
<
Or clone the plugin and run: >
  ./install.sh
<
The installer performs a locked release build of the daemon, atomically
installs `lib/simplegit-daemon`, and generates help tags. Building requires
Rust/Cargo 1.88 or newer. Rerun it after every update.

COMMANDS                                                   *simplegit-commands*

:SimpleGitBlame                                               *:SimpleGitBlame*
  Toggle a blame sidebar for the current file. The sidebar scrolls in sync
  with the file. Inside it: <CR> opens the commit under the cursor, `p` shows
  a popup with its details, `q` closes the sidebar.

:SimpleGitBlameLine                                       *:SimpleGitBlameLine*
  Show a popup with commit, author, date and summary for the current line.
  This blames only that line (`git blame -L`), so it is as fast on a large
  file as on a small one; the result is cached per line.

:SimpleGitToggleLineBlame                           *:SimpleGitToggleLineBlame*
  Toggle the inline current-line blame annotation.

:SimpleGitHistory                                           *:SimpleGitHistory*
  Open the commit history of the current file. Inside the window: <CR> shows
  the commit's changes to this file, `a` shows the whole commit, `q` closes.

:SimpleGitLog                                                   *:SimpleGitLog*
  Open the repository-wide commit graph (git log --graph) for the repository
  containing the current file (or the working directory for unnamed
  buffers). Inside the window: <CR> shows the commit under the cursor, `m`
  loads the next page of commits, `q` closes.

:SimpleGitDiff [rev]                                           *:SimpleGitDiff*
  Diff the current file against [rev] (default HEAD) in a vertical split.
  `q` in the revision buffer closes the diff. If you leave the originating
  window before the revision arrives, the diff is discarded rather than
  opening wherever you moved to.

:SimpleGitShow [rev]                                           *:SimpleGitShow*
  Show a commit (message, stats and patch). [rev] defaults to HEAD.

:SimpleGitStatus                                             *:SimpleGitStatus*
  Show the repository branch and changed files. The header adds `↑n`/`↓n`
  when the branch has diverged from its upstream. Inside the window: <CR>
  opens the file, `d` opens it and diffs it against HEAD, `a` stages it,
  `u` unstages it, `A` stages every repository change, `U` unstages the
  whole repository, `c` commits, `C` amends, `R` refreshes the list, `q`
  closes. A commit started here uses the repository the status view is
  showing, not the current working directory.
  With |g:simplegit_status_auto_refresh| enabled, FocusGained and ShellCmdPost
  changes are coalesced and refreshed in place after
  |g:simplegit_status_refresh_delay|. The reply validates the same window,
  buffer, repository, and generation and never changes the user's current
  tab/window/buffer. Explicit opens and in-place refreshes advance the same
  buffer generation, so a late reply of either kind cannot overwrite a newer
  one. Repository matching resolves symlinks and discovers the nearest `.git`
  directory or gitfile; sibling directories in one worktree therefore share
  refreshes, while distinct repositories do not. `R` refreshes immediately.
  Each refresh snapshots the selected path plus its fallback line. Reordered
  rows keep the cursor on the same file, and a rename matches either its new
  or original path. If that entry disappears, the nearest surviving row is
  used. Header and clean-placeholder selections remain valid. This cursor
  restoration is covered by the same target and generation checks, so a late
  response cannot move the cursor.

:SimpleGitStageAll                                   *:SimpleGitStageAll*
:SimpleGitUnstageAll                               *:SimpleGitUnstageAll*
  Stage or unstage every change in the repository containing the current
  buffer. These are the command equivalents of `A` and `U` in the status
  window; their scope is the repository root even from a nested directory.
  This is an additive protocol-5 capability. An older protocol-5 daemon is
  refused safely for these two commands only; rerun ./install.sh to enable
  them. All older operations remain available.

:SimpleGitCommit[!]                                          *:SimpleGitCommit*
  Commit what is staged. Opens a scratch buffer for the message; `:w`
  commits and `q` aborts. Lines starting with # are stripped, so the help
  text at the bottom never reaches the message. The message travels over the
  daemon's stdin rather than as a command-line argument, so blank lines,
  quotes and non-ASCII survive intact.
  Only one :write may be pending. Text entered after :write is never erased
  by the asynchronous success reply; it remains modified in the message
  buffer for an intentional follow-up commit.
  A message you have started but not written is never reopened over: while
  one is unsaved, this command refuses and says which tab it is in, so
  finish it with `:w` or abort it with `q` first.
  With [!] the previous commit is amended; its existing message is fetched
  and pre-filled, so amending edits the message rather than replacing it.

:SimpleGitHunkNext                                         *:SimpleGitHunkNext*
:SimpleGitHunkPrev                                         *:SimpleGitHunkPrev*
  Jump to the next/previous hunk (working tree vs index) in the current file.
  While the buffer is modified, hunks track the unsaved buffer contents,
  debounced by |g:simplegit_hunk_delay|. Pressed before the buffer's first
  refresh has answered, the jump is queued and runs as soon as it does, rather
  than being lost.

:SimpleGitHunkPreview                                   *:SimpleGitHunkPreview*
  Show the diff of the hunk under the cursor in a popup.

:SimpleGitHunkStage                                       *:SimpleGitHunkStage*
  Stage the hunk under the cursor into the index (like git add -p for one
  hunk). The buffer must be saved first; hunks reflect the file on disk.

:SimpleGitHunkUndo                                         *:SimpleGitHunkUndo*
  Revert the hunk under the cursor in the working tree and reload the
  buffer. This discards the change; it is not confirmed.

:SimpleGitToggleSigns                                   *:SimpleGitToggleSigns*
  Toggle the sign-column hunk markers.

:SimpleGitEnable  :SimpleGitDisable  :SimpleGitToggle        *:SimpleGitEnable*
  Control the whole plugin (daemon plus inline annotation).

:SimpleGitHealth                                             *:SimpleGitHealth*
  Print daemon path/version/protocol and feature support diagnostics.

CONFIGURATION                                         *simplegit-configuration*

g:simplegit_auto_enable (default 1)                   *g:simplegit_auto_enable*
  Start the plugin on VimEnter.

g:simplegit_line_blame (default 1)                     *g:simplegit_line_blame*
  Show the inline current-line blame annotation.

g:simplegit_blame_delay (default 350)                 *g:simplegit_blame_delay*
  Milliseconds after the cursor stops before the annotation appears.

g:simplegit_blame_format (default '%a, %w • %s')     *g:simplegit_blame_format*
  Layout of the inline annotation and of |simplegit#BlameAnnotation()|: >
    %a  author name          %h  short commit sha
    %e  author email         %d  commit date (YYYY-MM-DD)
    %s  commit summary       %w  relative time ("3 days ago")
    %%  a literal percent
<
  An unrecognised key is left as typed. Uncommitted lines always read
  "Uncommitted changes" regardless of the format. Changing this takes effect
  on the next annotation without refetching anything.

g:simplegit_blame_width (default 34)                  *g:simplegit_blame_width*
  Width of the :SimpleGitBlame sidebar.

g:simplegit_history_limit (default 200)             *g:simplegit_history_limit*
  Maximum commits fetched by :SimpleGitHistory.

g:simplegit_history_height (default 15)            *g:simplegit_history_height*
  Maximum height of the history window.

g:simplegit_log_limit (default 200)                     *g:simplegit_log_limit*
  Commits fetched per :SimpleGitLog page (`m` fetches the next page).

g:simplegit_log_height (default 20)                    *g:simplegit_log_height*
  Maximum height of the commit graph window.

g:simplegit_signs (default 1)                               *g:simplegit_signs*
  Show hunk markers in the sign column.

g:simplegit_sign_added (default '+')                   *g:simplegit_sign_added*
g:simplegit_sign_changed (default '~')               *g:simplegit_sign_changed*
g:simplegit_sign_removed (default '_')               *g:simplegit_sign_removed*
  Sign-column text for added, changed and removed lines.

g:simplegit_sign_priority (default 10)              *g:simplegit_sign_priority*
  Priority of the hunk signs.

g:simplegit_max_signs (default 500)                     *g:simplegit_max_signs*
  Above this many signs in one buffer none are placed.

g:simplegit_hunk_delay (default 300)                   *g:simplegit_hunk_delay*
  Milliseconds of typing rest before the live buffer-vs-index diff runs.

g:simplegit_status_refresh_delay (default 150)
                                    *g:simplegit_status_refresh_delay*
  Milliseconds to coalesce FocusGained and ShellCmdPost before refreshing an
  already-open status view. `R` and repository mutations issued from that
  status view refresh their exact target immediately and exclude only that
  repository from a pending global debounce; other repositories retain their
  scheduled refresh. Same-repository mutations without a target coalesce once.

g:simplegit_status_auto_refresh (default 1)
                                      *g:simplegit_status_auto_refresh*
  Refresh an existing status view after FocusGained and ShellCmdPost. Set to
  0 to disable those automatic reads. Explicit status commands and targeted
  refreshes after SimpleGit's own mutations remain available; disabling the
  plugin is always a hard boundary and cannot restart the daemon.

g:simplegit_live_max_bytes (default 1048576)       *g:simplegit_live_max_bytes*
  Buffers larger than this fall back to the on-disk diff until saved.
  Below it, the unsaved text is handed to git through a temporary file in a
  private per-daemon directory (0700, files 0600, refusing to write through
  an existing path), removed as soon as the diff returns.

g:simplegit_daemon_path (default '')                  *g:simplegit_daemon_path*
  Absolute path of the daemon binary; overrides runtimepath discovery.

g:simplegit_enable_default_mappings (default 1)
                                            *g:simplegit_enable_default_mappings*
  Install the <leader>g* default mappings.

g:simplegit_debug (default 0)                               *g:simplegit_debug*
  Echo daemon/protocol diagnostics with :echomsg.

STATUSLINE API                                           *simplegit-statusline*

A stable public surface for statusline plugins, so nothing has to run its own
`git` to show a branch and a change count. Everything below reads caches
Simplegit already maintains: the accessors are O(cached hunks), never dispatch
a request and never block, which is what makes them safe in 'statusline',
where they are re-evaluated on every redraw.

simplegit#StatusLine([{bufnr}])                        *simplegit#StatusLine()*
  A ready-made segment for {bufnr} (default: the current buffer), for
  example: >
    main ↑2 ↓1 +12 ~3 -1
<
  `↑`/`↓` are commits ahead of and behind the upstream; `+`/`~`/`-` are added,
  changed and removed lines in this buffer against the index. Zero values are
  omitted. The result is empty while the branch is still unknown and for a
  buffer that belongs to no repository, so it can be concatenated
  unconditionally: >
    set statusline+=%{simplegit#StatusLine()}
<
simplegit#StatusDict([{bufnr}])                        *simplegit#StatusDict()*
  The same information as a dictionary, for a custom renderer: >
    {'head': 'main', 'ahead': 2, 'behind': 1,
     'added': 12, 'changed': 3, 'removed': 1}
<
  Every key is always present. An unknown branch is an empty `head`, never a
  missing key.

simplegit#Head([{bufnr}])                                    *simplegit#Head()*
  The branch name of {bufnr}'s repository, the short sha when HEAD is
  detached, or an empty string while it is still unknown.

simplegit#HunkSummary([{bufnr}])                      *simplegit#HunkSummary()*
  `{'added': n, 'changed': n, 'removed': n}` — line counts folded from the
  same hunks that drive the sign column, so they track unsaved edits exactly
  as the signs do.

simplegit#BlameAnnotation([{bufnr} [, {lnum}]])  *simplegit#BlameAnnotation()*
  The inline blame annotation for one line, rendered through
  |g:simplegit_blame_format| — the same string the virtual text shows. Empty
  while that line's blame is still unknown. {lnum} defaults to the cursor
  line of the current buffer. Like the other accessors it only reads caches,
  so it never fetches a line that has not been annotated yet.

b:simplegit_status_dict                              *b:simplegit_status_dict*
  Every file buffer carries the |simplegit#StatusDict()| result, updated
  whenever its hunks or its branch change. This is the
  `b:gitsigns_status_dict` equivalent.

User SimpleGitUpdate                                    *SimpleGitUpdate*
  Fired after b:simplegit_status_dict changes, so a consumer can redraw: >
    autocmd User SimpleGitUpdate redrawstatus!
<
  It carries no payload; read b:simplegit_status_dict of the buffer being
  rendered. The event is raised only when something is listening for it.

The branch is read once per repository — not per buffer — by a `branch`
request that reads two refs and never walks the worktree, issued from the
buffer lifecycle and re-read after |FocusGained| and |ShellCmdPost|. It is an
additive protocol-5 capability: against an older daemon that does not
advertise `branch_summary`, `head` stays empty and |simplegit#StatusLine()|
returns an empty string rather than sending a request the daemon cannot
answer. |:SimpleGitHealth| reports which. The hunk counts do not depend on
that capability.

TROUBLESHOOTING                                     *simplegit-troubleshooting*

Run |:SimpleGitHealth|. "daemon binary: (not found)" means ./install.sh has
not produced lib/simplegit-daemon (or set |g:simplegit_daemon_path|). A
version of "unknown/0" that persists means the binary is outdated — rerun
./install.sh. "whole-repo ops: unavailable" means Vim negotiated protocol 5
with an older daemon that does not advertise repository_file_ops; those two
commands fail closed rather than sending an ambiguous request. Inline
annotations require Vim with virtual-text support
(patch 9.0.0067+); the blame sidebar and popups work without it.

The inline annotation intentionally disappears while the buffer is modified:
blame data reflects the file on disk, and edited line numbers would no longer
match. Save the buffer to refresh it.

The annotation blames one line at a time (`git blame --porcelain -L n,n`) and
caches the answer per line, so a file with deep history annotates as quickly
as a shallow one. The blame sidebar still reads the whole file in one request,
and while that result is cached every annotation is served from it. An older
daemon that does not advertise the `blame_line` capability keeps the previous
whole-file behaviour; |:SimpleGitHealth| reports which.

DAEMON SUPERVISION                                    *simplegit-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simplegit/core.vim; that file is generated, do not edit it in place.

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :SimpleGitRestart re-arms it.
- Requests are correlated to replies by id and can time out, so a wedged
  daemon never leaves a callback hanging.
- Protocol 5 also negotiates additive capabilities. Whole-repository file
  operations require repository_file_ops, the |simplegit-statusline| branch
  requires branch_summary and single-line blame requires blame_line; a
  protocol-5 daemon without any of them is still usable for every older
  request.
- The live buffer-vs-index diff writes the unsaved buffer to a private
  per-daemon scratch directory rather than a predictable $TMPDIR path, so
  unsaved text is never readable by other users on a shared machine and a
  planted symlink cannot redirect the write.
- Hunk stage/undo, file stage/reset and commit operations share one FIFO
  index lane. They complete in request order and cannot race each other for
  .git/index.lock; read-only blame/log/status work remains concurrent.
- An asynchronous status/commit completion remembers its initiating tab,
  window, buffer and repository. It refreshes only that still-live status
  view, discards stale generations (initial status requests are latest-wins),
  and never changes the user's current focus or recreates a view that was
  closed. Commit replies also preserve any message text typed after :write.
- The views opened by a reply — |:SimpleGitShow|, |:SimpleGitHistory|,
  |:SimpleGitLog| and |:SimpleGitDiff| — carry the same guard. If you move to
  another window or tab, or the origin window moves to another repository,
  before the reply lands, it is discarded instead of opening a split where you
  now are; a newer request for the same view supersedes an older one. Reusing
  an existing scratch window is scoped to the current tab, so a view never
  drags you into the tab that opened it first; a copy owned by another tab is
  retired. Unsaved text is protected by refusing the command that would
  discard it -- see |:SimpleGitCommit| -- never by reusing a buffer that
  still holds it.

:SimpleGitHealth
        Report daemon path, run state, negotiated protocol and capabilities,
        uptime, crash and restart counts, and whether the crash-loop breaker
        has tripped, alongside this plugin's own diagnostics.

                                                      *:SimpleGitRestart*
:SimpleGitRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

                                                      *:SimpleGitDaemonLog*
:SimpleGitDaemonLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.


==============================================================================
DAEMON COMMAND LINE                                      *simplegit-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simplegit-daemon --version
  simplegit-daemon --help
  simplegit-daemon --self-test
<
--self-test runs one request through the daemon in-process and prints "ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                                      *simplegit-simplecore*

The daemon supervisor in autoload/simplegit/core.vim, and the test harness
beside it, are vendored from the suite's shared .simplecore bundle rather
than written here — each plugin carries its own copy so that installing
this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
